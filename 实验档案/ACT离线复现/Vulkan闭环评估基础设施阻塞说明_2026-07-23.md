# ACT RGB 闭环评估的 Vulkan 基础设施阻塞说明

## 结论

当前训练容器可以运行 CUDA、GPU PhysX 与 ACT 离线训练，但不能完成官方等价的 RGB 50-seed 闭环评估。原因不是 ACT checkpoint 或 RTX 3090 算力不足，而是容器未被授予 NVIDIA graphics/Vulkan capability。

## 为什么 DP 可以评估而 ACT 不可以

DP 使用 `obs_mode=state`。评估时直接从仿真读取低维 state tensor，`warehouse_sort/utils.py` 会将 `render_backend` 设为 `none`；因此 GPU PhysX 只需计算能力，不必创建 camera renderer。DP 的 Easy、Medium、Hard 都在固定 50 episode 下完成了无视频 headless 评估。

ACT 使用 `obs_mode=rgb`。policy 需要 `obs["rgb"]`，该观测来自 scene camera；即使 `record_video=false`，环境仍必须建立 GPU renderer 来生成每一步的 RGB 图像。RGB 路径会使用 `render_backend="gpu"`，因此依赖 SAPIEN 可访问的 NVIDIA Vulkan device。

## 已验证的证据

- 容器内 ACT 可读取原始 RGB H5，完成 30,000 updates，并保存可加载的 EMA checkpoint。
- CUDA/GPU PhysX 可用，但 `/dev/dri` 未暴露，Vulkan 不能创建可与 CUDA 设备互操作的 NVIDIA renderer。
- Mesa fallback、GPU PhysX + llvmpipe，以及匹配版本 NVIDIA ICD 都已尝试；llvmpipe 是 CPU renderer，不能替代 NVIDIA Vulkan。
- 因此 CPU fallback 的 `sort_accuracy` 不能代表官方 GPU RGB 条件，也不能据此判断 ACT 或榜一 checkpoint 的真实性能。

## 对服务器管理员的要求

需要重新创建或配置容器，暴露完整 NVIDIA graphics capability，而不是只暴露 compute：

```bash
docker run --gpus all \
  -e NVIDIA_VISIBLE_DEVICES=all \
  -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics \
  ...
```

在容器内依次确认：

```bash
nvidia-smi
ls -l /dev/nvidia* /dev/dri
vulkaninfo --summary
```

只有 `vulkaninfo` 能识别 NVIDIA GPU，且 SAPIEN 能创建 RGB environment 后，才能运行：

```bash
pixi run python eval.py difficulty=easy \
  policy=warehouse_sort.act_policy:load_act \
  checkpoint=PATH_TO_ACT_CHECKPOINT \
  eval_config=conf/eval/server_50.yaml
```

在上述运行输出官方 `sort_accuracy` 前，ACT 的结论应保持为：离线训练复现完成，闭环性能未知。
