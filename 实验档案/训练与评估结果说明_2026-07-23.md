# WarehouseSort 训练与评估结果说明

## 1. 本文的结论边界

本项目完成了 State Diffusion Policy（DP）的多阶段训练和 state 闭环评估，也完成了 Easy RGB ACT 的离线训练复现。不能将这两类产物混为同一种结果：DP 已有可复跑的闭环 `sort_accuracy`；ACT 目前只有离线训练和 checkpoint 健全性证据，闭环性能仍未知。

最终应报告的 DP 定版复验结果是：Easy `0.390`、Medium `0.090`、Hard `0.103`。它们均来自官方 loader、无视频 state 环境和固定 50 episodes。最终选中的来源分别是 Easy 基线 `seed=3`、Medium 基线 `seed=1`、Hard 扩充数据 `batch=512, seed=3`。因此，“扩充数据后的 DP 比基线更差”不是总体结论；它只对 Medium 成立，Hard 的最终候选来自扩充数据。

## 2. 任务指标：`sort_accuracy` 到底衡量什么

WarehouseSort 的一个 episode 有固定数量的包裹：Easy 为 2、Medium 为 4、Hard 为 6。每个包裹有目标 bin 标签。episode 结束后，环境检查每个已释放包裹是否落在目标箱的范围内。

设第 `i` 个 episode 的正确分拣包裹数为 `c_i`，该难度的包裹数为 `P`，评估总 episode 数为 `N`。主指标为：

```text
sort_accuracy = sum(c_i, i=1..N) / (N * P)
```

它是所有包裹层面的正确分拣比例，而不是“episode 全部成功的比例”。例如 Easy 的 `sort_accuracy=0.390`，等价于 50 个 episode、共 100 个包裹中有 39 个正确进入目标箱；日志中的 `mean_sorted=0.78/2` 是同一事实按“每个 episode 平均正确包裹数”表达。

环境还记录三个辅助诊断指标：

| 指标 | 定义 | 解释 |
|---|---|---|
| `mean_sorted` | `sum(c_i) / N` | 每个 episode 平均正确放置的包裹数 |
| `all_placed_rate` | 所有包裹都进入任一 bin 的 episode 比例 | 反映是否完成搬运，但不保证放对箱子 |
| `mis_sort_rate` | 错放进非目标 bin 的包裹数 / `N*P` | 反映错误投放；未放入任何箱子不计为误分拣 |

因此，`all_placed_rate=0` 不等于策略完全没有动作或完全没有进展。它表示没有一个 episode 把全部包裹放进箱子；在当前结果中，策略仍有部分包裹被正确分拣，所以 `sort_accuracy` 非零。任务的完整成功条件是 `all_placed=true`，即全部包裹至少进入某个 bin；高质量完成还要求这些包裹都在各自目标 bin，故完整且正确的 episode 必然同时提高 `all_placed_rate` 和 `sort_accuracy`。

## 3. DP 的三类评估及其用途

### 3.1 训练损失

DP 训练过程中的损失用于确认优化过程在运行，但它不是任务成功指标。损失下降说明策略越来越能拟合示范动作分布，不能单独证明策略在闭环物理仿真中能抓取、搬运并正确分拣包裹。

### 3.2 训练内评估

DP 训练脚本定期用 EMA 权重在小批量环境中运行评估，并把 `sort_accuracy` 等指标写入训练日志。训练脚本会以该内部评估中的最佳 `sort_accuracy` 保存 `best_eval_sort_accuracy.pt`。这个机制的用途是从单次训练过程挑选 checkpoint，不是最终比较。

批次 01 的训练内最高值为 Easy `0.4688`、Medium `0.1719`、Hard `0.0833`；批次 02 延长训练为 Easy `0.5625`、Medium `0.2500`、Hard `0.0938`。这些数值来自训练期间的 16-episode 小样本评估，种子和样本量均不等同于最终固定评估。它们明显高于后续一些 50-seed 分数，正说明小样本波动和 checkpoint 选择偏差不能被当作最终成绩。

### 3.3 固定 50-seed 独立闭环评估

正式比较使用 `seeds=5000..5049` 的 50 个 episode，state 观测、GPU PhysX、headless、禁用视频。每个候选 checkpoint 在训练进程之外经官方 loader 载入后运行完整 episode，最终由环境累计正确包裹数并计算上述 `sort_accuracy`。50 个 episode 使用相同的难度、评估配置和 seed 集，因此可用于同一难度内比较候选。

这个评估回答的是“该 checkpoint 在固定的未参与训练评估的场景集合中，实际完成了多少正确分拣”。它仍是有限样本估计，不应被解读为所有随机初始条件上的真实性能；但它比训练内 16-episode 指标更适合做候选保留和复现实验对比。

## 4. DP 分阶段结果

### 4.1 200 条示范的基线训练

每个难度各使用 200 条 state 示范。基线的固定 50-seed 结果如下：

| 难度 | 训练配置 | 固定 50-seed `sort_accuracy` | 说明 |
|---|---|---:|---|
| Easy | `seed=1`，30k updates，batch 256 | 0.170 | 平均每 episode 正确 `0.34/2` 个包裹 |
| Medium | `seed=1`，50k updates，batch 256 | 0.110 | 平均每 episode 正确 `0.44/4` 个包裹 |
| Hard | `seed=1`，60k updates，batch 256 | 0.037 | 平均每 episode 正确 `0.22/6` 个包裹 |

该阶段的加权分数记录为 `0.0855`。它证明 state DP 的训练、加载和闭环评估链路可用，但完整分拣成功率仍很低。

### 4.2 延长训练

在同一 200 条数据上增加迭代数后，固定 50-seed 结果为 Easy `0.170`、Medium `0.080`、Hard `0.040`。因此 Easy 与基线持平，Medium 下降，Hard 从 `0.037` 小幅升至 `0.040`。此阶段仅保留 Hard 的延长训练候选；不能以较高的训练内 `sort_accuracy` 宣称三项均有提升。

### 4.3 扩充示范数据

扩充后，Medium 使用 400 条成功示范，Hard 使用 600 条成功示范；Easy 没有扩充。第一轮扩充数据候选的固定 50-seed 结果为 Medium `0.055`、Hard `0.053`。相对各自保留候选，Medium 从基线 `0.110` 降低，Hard 则从延长训练 `0.040` 提升。

继续调整 batch size 和随机种子后，Hard 的扩充数据候选达到 `0.087`（`batch=512, seed=1`），三随机种子中最高为 `0.107`（`batch=512, seed=3`）。Medium 的扩充数据没有超过其基线。因此数据扩充的证据是“有难度依赖性”：它对 Hard 有正向候选，对 Medium 没有带来收益。

### 4.4 定版 checkpoint 的干净复验

最终封存的 `state_*_best.pt` 再次使用官方 loader、50 episodes、50 次推理步和 Torch/CUDA RNG seed 0 复验。Easy 进行了重复运行并得到同一结果。

| 难度 | 定版 checkpoint 的训练来源 | 定版 50-episode `sort_accuracy` | 可报告解释 |
|---|---|---:|---|
| Easy | 基线，200 条示范，`seed=3` | 0.390 | 最优来源是基线；重复复验一致 |
| Medium | 基线，200 条示范，`seed=1` | 0.090 | 扩充数据未优于基线来源 |
| Hard | 扩充数据，600 条示范，`batch=512, seed=3` | 0.103 | 最优来源是扩充数据 |

这些定版复验使用的 RNG 设置与候选筛选日志不同，数值不能与早期候选表逐项当作同一次随机试验的增减比较；它们的作用是确认最终二进制 checkpoint 在明确、可复跑条件下的闭环输出。三项按报告权重 `0.50/0.30/0.20` 汇总为 `0.2421`。

## 5. ACT：离线训练、离线检查与闭环评估的区别

ACT 使用 Easy RGB 数据：200 条成功轨迹、23,000 个 transitions，训练 30,000 updates，batch size 32，学习率 `1e-4`，KL weight 10，30 个 action queries。模型为 ResNet-18 backbone、DETR/CVAE 和 EMA。

### 5.1 ACT 的训练 loss

每个 update 的总损失是动作序列重建 L1 损失与 KL 正则项的加权和：

```text
total_loss = L1(action_prediction, demonstration_action) + 10 * KL
```

训练日志从 iteration 0 的 `88.0554` 降至 iteration 29,000 的 `0.0123`，中间存在正常的小幅波动。这个趋势表明优化器、数据读取、前向反向传播和 EMA 都在工作；它衡量的是离线示范动作的拟合误差，不含环境交互，不能转换成任何 `sort_accuracy` 或成功率。

### 5.2 ACT 的离线 checkpoint 检查

最终 EMA checkpoint 已独立加载和推理：输出 shape 为 `(2, 4)`，数值均为有限值，检查样本动作范围为 `[-0.211787, 0.621868]`。这证明 checkpoint 文件可读取、网络结构和归一化统计可用、推理没有 NaN/Inf；它不证明相机观测、时序集成、机械臂控制和物理交互在闭环中正确。

### 5.3 为什么 ACT 没有训练内或固定 50-seed 闭环分数

原始 ACT 训练每隔 `eval_freq` 本应创建 RGB 环境，用 EMA 模型运行环境评估，并按 `sort_accuracy` 保存最佳 checkpoint。当前容器无法创建该 RGB 环境：ACT 每一步都需要 scene camera 产生 `obs["rgb"]`，这要求 SAPIEN 使用可与 CUDA 互操作的 NVIDIA Vulkan renderer。容器只有 CUDA/GPU PhysX 的计算能力，未暴露可用的 NVIDIA graphics/Vulkan capability。

为使训练本身可完成，运行使用 `--skip-env-eval`。该选项跳过所有在线环境评估和“按 online `sort_accuracy` 保存最佳 checkpoint”，不改变离线数据读取、模型、loss、优化器或 EMA。因此当前没有 ACT 的训练内闭环曲线，也没有 ACT 的官方形式 Easy 50-seed 分数；CPU llvmpipe fallback 的结果不能代替 GPU RGB 条件。

## 6. ACT 闭环评估的完成标准与下一步

完成 ACT 闭环评估需要一个同时满足 CUDA、GPU PhysX 和 NVIDIA Vulkan graphics 的容器。管理员应暴露 `/dev/dri` 并启用 `NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics`；在容器内确认 `nvidia-smi`、`vulkaninfo --summary` 和 SAPIEN RGB environment 都能识别同一 NVIDIA GPU。

随后使用正式 ACT checkpoint、`warehouse_sort.act_policy:load_act` 和 `conf/eval/server_50.yaml` 在 Easy 上运行固定 50-seed 评估。只有命令完整结束并输出 `SORT ACCURACY`、`mean_sorted`、`all_placed_rate` 与 `mis_sort_rate` 后，才可报告 ACT 的闭环结果，并与 DP 的对应指标分开比较。
